## 项目简介

moon-agent-reactor 是一个纯 MoonBit 实现的 AI Agent 运行时，核心是 ReAct（Reason + Act）循环：Agent 在每一步先产生推理文本，再决定调用某个工具，拿到观察结果后继续推理，直到得出最终答案或达到迭代上限。项目同时提供类型安全的工具注册表、短期对话记忆与长期知识库、基于 DAG 依赖的任务规划，以及可替换的 LLM 后端抽象（Mock、OpenAI 兼容、Ollama 本地模型均可接入）。

选择纯 MoonBit 实现而不绑定某个具体模型服务，主要出于两点考虑：一是 Agent 的编排逻辑（循环、工具分发、记忆管理）本身与模型无关，值得抽成独立基础库；二是编译到 wasm/wasm-gc 后可以直接跑在浏览器或边缘环境里，这是 Python 系 Agent 框架做不到的。

## 项目方向与通用性

本项目属于"AI 应用"方向下的基础设施层，不面向终端用户，而面向在 MoonBit 生态中构建 Agent 应用的开发者。工具系统、记忆接口、LLM 后端均为 trait 抽象，任何第三方库都可以按接口接入，不与本项目产生耦合。

## 预期使用场景

**场景一：本地知识问答助手。** 开发者用 Ollama 起一个本地模型，注册"检索本地文档"和"计算器"两个工具，即可得到一个不出内网的问答 Agent。推理与工具调用全程在本地完成，适合对数据隐私敏感的内部工具场景。

**场景二：浏览器内的多步推理组件。** 项目编译到 wasm-gc 后嵌入网页，前端页面无需自建后端即可获得带工具调用能力的 Agent。例如在线表格工具中嵌入一个"分析当前选中数据"的 Agent，其工具直接读写页面状态。

**场景三：自动化研究流水线。** 结合规划模块，把"搜索资料—提取要点—汇总成文"分解为带依赖的子任务图，由 Agent 按拓扑顺序执行，中间结果写入长期知识库供后续任务复用，构成可复现的研究型流水线。

## 拟实现的核心功能

- ReAct 推理循环：Thought / Action / Observation 状态机，支持最大迭代数、出错续跑等配置；
- 工具系统：以参数元数据描述工具签名，注册表统一分发调用，并生成面向 LLM 的工具说明文本；
- 记忆系统：滑动窗口式短期对话记忆，带重要度评分与分类检索的长期知识库；
- 任务规划：子任务依赖图，自动计算可执行任务集合，失败不阻塞无依赖分支；
- LLM 抽象：chat 接口统一收口，Mock 后端用于测试，OpenAI 兼容后端覆盖主流云端与本地部署（Ollama、vLLM 等）。

## 原创性说明与同类项目调研

本项目为原创设计，未移植任何现有项目的代码。报名前我们对 MoonBit 生态做了检索，结论如下：

- **moonbitlang/openseek**（2026-08）：定位是接入 DeepSeek 的编码助手，属于"用 LLM 辅助写 MoonBit"，不含 Agent 编排能力，与本项目不构成选题重叠；
- **moonbitlang/workflow**（2026-09）：多人协作的工作流引擎，处理的是人工节点编排，不涉及 LLM 推理循环与工具调用；
- **extism/moonbit-pdk**：Extism 插件开发工具包，解决的是"WASM 插件如何被宿主调用"，与 Agent 运行时的关注点不同；
- **bytecodealliance/wit-bindgen 的 MoonBit 后端**（PR #1020）：这是 Rust 写的绑定生成工具，MoonBit 只是它的目标语言之一，与本项目在实现语言和定位上均无交集。

此外也调研了 Python 生态的 LangChain / AutoGen 等。它们验证了 ReAct 模式的可行性，但均无法编译到 wasm，也不适合作为 MoonBit 生态的依赖。本项目的差异点在于：推理循环、记忆、规划三者均以 MoonBit 原生 trait 暴露，且整条链路可以在 wasm 环境中闭环运行。
